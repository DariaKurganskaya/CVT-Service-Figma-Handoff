# Предпубликационные блокеры

Этот файл внутренний: он не входит в статическую папку `out/` и не предназначен для посетителей.

## Обязательно решить до запуска форм

1. **Доступ к заявкам.** Клиент должен подтвердить сотрудников или подрядчиков и их роли, которым разрешён доступ к заявкам.
2. **Срок хранения.** Оператор должен утвердить срок хранения, удаление и/или обезличивание заявок.
3. **Роскомнадзор.** Оператор должен принять решение о необходимости уведомления Роскомнадзора.
4. **Трансграничная передача.** Оператор должен подтвердить, есть ли она при использовании почты и других выбранных сервисов.
5. **Beget.** До запуска следует подтвердить место обработки и хранения данных на выбранной конфигурации Beget.

## Нужны только перед подключением соответствующего сервиса

1. Яндекс Метрика: найти идентификатор уже существующего счётчика. Новый счётчик не создавать.
2. Callibri или другой выбранный коллтрекинг.
3. CRM: название, порядок передачи заявок и получатели.
4. MAX: публичная ссылка на профиль или приглашение.

## Подтверждённая схема заявок

- Единственный канал доставки: `форма → PHP → info@remontvariator.ru`.
- Telegram не является каналом доставки заявок и не является блокером. Публичная Telegram-кнопка остаётся обычной ссылкой для связи.

## Незавершённые формулировки в юридических страницах

Не менять без подтверждений клиента:

- `/privacy-policy/`: «будут уточняться по мере их подключения»;
- `/privacy-policy/`: «должны быть уточнены клиентом» о получателях и сервисах;
- `/privacy-policy/`: «Конкретный срок хранения заявок должен быть утверждён оператором»;
- `/privacy-policy/`: «Конкретный состав мер зависит от выбранного хостинга...»;
- `/personal-data-consent/`: «если иной срок не будет установлен оператором в окончательной редакции документов»;
- `/cookie-policy/`: «Идентификатор счётчика пока не предоставлен»;
- `/cookie-policy/`: «этот документ должен быть обновлён до их подключения».
