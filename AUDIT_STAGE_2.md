## 7. Техническая совместимость с Beget

**Фактический стек:** Next 16 / React 19, собранный Vinext через Vite, плагины Cloudflare и ChatGPT Sites. Это не готовая обычная статическая папка для Beget.

**Статическая сборка:** достижима после отдельной адаптации. Сейчас ей мешают `headers()` в `app/layout.tsx`, динамические metadata и Cloudflare/Vinext-цепочка. При простом static export перестанет корректно формироваться metadata от host, а формы и будущие серверные маршруты работать не будут.

**Рекомендуемый вариант:** статический frontend (HTML/CSS/JS/assets) на обычном виртуальном Beget + отдельный PHP-обработчик `/api/lead.php` для обеих форм. Он сохраняет утверждённую визуальную версию, не требует Node/Cloudflare runtime и подходит для почты/Telegram. Нужны: HTTPS, PHP 8.2+, возможность исходящих SMTP или API-запросов и закрытые env/конфигурация вне web-root. Node.js-вариант допустим только после отдельной проверки возможностей выбранного тарифа; на этом этапе он не рекомендуется.

**Заменить/удалить позже:** `.openai/hosting.json`, `vite.config.ts`, `build/sites-vite-plugin.ts`, Cloudflare/Vinext/Wrangler зависимости, `examples/d1/`, `db/` и `app/chatgpt-auth.ts` — после подтверждения, что они не используются новой архитектурой. `README.md` заменить на проектный. `package-lock.json` оставить до окончания миграции как воспроизводимый снимок. Неиспользуемые assets, замеченные статически: `about-workshop-real.jpg`, `autorizen-logo.png`, `client-logo-red.png`, `client-logo-white-red.png`, `cvt-hero.png`, `file.svg`, `globe.svg`, `service-team.webp`, `service-workshop.webp`, SVG-версии social и `window.svg`; удалить только после проверки новой сборки. Старые Figma-handoff/скриншоты/`sections-*.json` в этой ветке отсутствуют и не должны возвращаться в production.

## 8. Рекомендуемая схема заявок

**Данные:** имя, телефон, сообщение, дата/время, технический идентификатор обращения; не собирать лишнее. **Поток:** обе формы → HTTPS `POST /api/lead.php` → серверная нормализация телефона и валидация → одновременное письмо на рабочую почту и уведомление Telegram → единый нейтральный ответ фронтенду. SMTP/API token хранятся в env/конфигурации вне публичной директории. Не логировать текст сообщения дольше необходимого.

## 9. Рекомендуемая схема антиспама

| Вариант | Плюсы | Минусы | Решение |
|---|---|---|---|
| CAPTCHA на каждой заявке | Высокий барьер для ботов | Снижает конверсию, хуже для российских пользователей | Не применять по умолчанию |
| Honeypot + минимальное время заполнения + server rate-limit + CAPTCHA при подозрении | Нет лишнего шага для обычного клиента, защита на сервере, адаптируется к атакам | Нужны серверная логика и журналирование событий | **Рекомендуется** |

Параметры: скрытое поле-honeypot; отказ при заполнении быстрее 3–5 секунд; лимит по IP/телефону на короткое окно; серверная валидация; CAPTCHA только после превышения лимита/подозрительных признаков; журналировать событие и причину, а не полный текст персональных данных.
